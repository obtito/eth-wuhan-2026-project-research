# 研究方向全记录

此文保存讨论过的四个初版项目及其演变。它们是设计建议，不是已经完成的应用。当前推荐以[项目设计与已有工作审查](项目设计与已有工作审查.md)为准。

## 研究过程与材料

1. 从 AdventureX Gallery 筛选区块链相关候选，形成项目清单及结构化数据。
2. 深化 29 个重点案例，区分 26 个核心强相关项目和 3 个补充关联项目。
3. 将原始案例的机制映射到 GCC 与 BOT Chain 赛道。
4. 查找 GitHub 实现参考，提出两个赛道各两个初版设计。
5. 与已有协议、开源项目和商业产品对照，收窄三个方向，撤下通用任务托管方案。

这里只保存研究结果、来源与方案归纳，不将未确认的产品宣传当作独立验证结论。

## 初版一：验真——Agent 服务验收与公共信誉

**赛道：** GCC 的 Agent 公共信誉与服务验收。

**原始模板：** Huozi 的能力采购、CarryPilot 的确定性检查、QuakeFeel 的证据记录。

**用户需求：** Agent 采购陌生链上数据服务时，历史身份和评分不能保证当前结果可用；需要选择服务、验收结果、失败换源，并留下可供后续使用者参考的公共证据。

**初版流程：** 提交查询任务 → 比较服务范围、价格和历史表现 → 采购结果 → 检查链、区块、日志覆盖及新鲜度 → 失败切换服务 → 生成公共验收记录。

**最小版本：** 两个服务（正常服务和可注入故障的服务）、一种查询、确定性检查器、公共回执和重放功能。使用分任务指标，显示样本数量，限制重复反馈，避免万能星级。

**实现参考：** Agent0、ERC-8004、x402-receipts。身份、支付和签名只能承担对应职责，不能替代成果真实性验证。

**审查与演变：** TrustMyChoice 和 AgentProof 已覆盖大量原始定位。改为“Agent 决策故障归因”，把服务违约与跨服务数据不兼容、调用方错误分开，避免公共信誉错误归责。

## 初版二：链上案卷——异常清算调查

**赛道：** GCC 的以太坊链上异动调查 Agent。

**原始模板：** CarryPilot、xEngine、EtaPanel。

**用户需求：** 发现异常清算之后，需要理解原因、潜在影响与证据，而非只有图表或报警。

**初版流程：** 在 Aave V3 Ethereum 的一个历史范围内识别异常 → Agent 提出价格、仓位与参数变化等解释 → 读取历史数据和状态 → 检查解释 → 输出事件案卷、证据和不确定性。

**最小版本：** 一个协议、一个历史事件、可复算指标、有限的调查假设及证据报告。不做全链实时调查或自动交易。

**实现参考：** QuickNode Aave Liquidation Tracker、Blockscout MCP；量化计算与 Agent 解释分别评价。

**审查与演变：** Chainalysis 等产品已经覆盖通用调查和报告，模拟也已有工具。收窄到“链上结论质检员”：输入一条现有解释，检验支持证据、反例和缺口，说明何种额外证据能区分竞争解释。

## 初版三：算力拼团——需求驱动的 AI 服务清算

**赛道：** BOT Chain。

**原始模板：** Makebook 的最高愿付、起订量、阶梯报价与统一清算，以及 injectiveAiHub 的 AI 服务供给。

**用户需求：** 多位买家的小额需求可能通过共同执行获得优惠，并需要公开的出资和退款规则。

**初版流程：** 买家锁定最高预算 → 供应方冻结起订量和阶梯报价 → 到期统一清算 → 实际运行任务 → 验收交付 → 成交退款差额或未成团退款。

**最小版本：** 一个批次、一种公开图片向量化服务、成团清算与失败退款、真实服务调用。验收者及其信任边界明确披露，不宣称全部执行无须信任。

**审查与演变：** 批量推理和算力竞价已经存在。改为“合算”，先检查模型、版本、预处理、期限和数据共享约束，证明加入全部成本后仍有净收益，再共同付款。不能依靠假设折扣或人为抬高单买价格证明价值。

## 初版四：任务保——Agent 协作任务验收托管

**赛道：** BOT Chain。

**原始模板：** PolyAgentMarket 的任务协作、Huozi 的服务采购、FactMatch 的承诺与资金规则。

**用户需求：** 自然语言需求难以直接成为付款条件；需要在工作前约定可检查的任务与交付要求。

**初版流程：** 自然语言需求 → 冻结输入哈希、输出结构、去重规则、期限和预算 → 资金托管 → 服务提交成果 → 检查器验收 → 付款、拒绝或到期退款。

**最小版本：** 两个服务、一种 CSV 清洗任务、五类业务状态、托管合约及确定性检查器。

**审查结论：撤下原版。** ERC-8183 已覆盖托管、提交、验收、拒绝及到期退款；BOT Chain 的 Agent Escrow 参赛页描述了同链类似项目。部分付款、失败任务重派和里程碑也已有方案，因此不足以作为补救创新。

保留为通用实现参考，不将改名、部署到另一条链或新增聊天界面当作核心创新。

## 当前选择

| 方向 | 当前状态 | 需要证明的贡献 |
| --- | --- | --- |
| Agent 决策故障归因 | GCC 首选 | 可重放的错误定位与公平归责 |
| 链上结论质检员 | GCC 备选 | 可被反例修正的解释与证据缺口 |
| 合算 | BOT 首选，先验证经济可行性 | 任务兼容性与实测净收益 |
| 任务保原版 | 撤下推荐，保留研究记录 | 原版没有充分差异化 |
